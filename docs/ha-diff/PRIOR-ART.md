## Decision

Existing tools already cover trace collection, viewing, timing comparison and CCA-specific progression. Do not rebuild those. Build a **thin offline Home Assistant adapter around DeepDiff + jsonpointer** for the narrow remaining gap: compare recorded triggers, variables, outcomes and reached paths across two downloaded runs, with verifiable references into both original files. It does not execute templates, infer device state, simulate HA or claim causality.

The native export or raw `trace/get` payload is required. Trace Viewer's privacy-reviewed summary export lacks the data needed here. The docs give both native-download and raw-payload integration recipes; Testkit's wrapper fixture is supported without importing its GPL parser.

Home Assistant's `homeassistant/helpers/trace.py`, `homeassistant/components/trace/models.py`, `tests/components/trace/test_websocket_api.py` were inspected at tag `2026.11.1`. ## Verified integration details after the first version

Core 2026.11.1 sets repeat.index directly for each loop iteration and caps repeated action nodes at 20 entries, discarding older entries. These source facts informed conservative direct-index alignment and retention warnings; no engine state is reconstructed. Frontend dev commit 5253eef284e3bcb336c721821ec7751bb3bde3ee was checked for getDataFromPath, getNestedStepConfig and flattenTriggers. The adapter preserves raw configuration pointers for these existing normalization rules; detailed source links and scope are in [ALIGNMENT.md](ALIGNMENT.md) and [CONFIGURATION.md](CONFIGURATION.md).

The runtime ultimately uses the pure-Python DeepDiff 8.6 line (locked 8.6.2). A binary-only 9.1.0 install on Python 3.15 reproduced an unavailable cachebox 5.x wheel; 8.6.1 then passed 87 source tests on 3.15, and the locked 8.6.2 passed the full main suite and fresh installed-wheel checks on 3.11/3.15. This is a dependency compatibility choice, not a replacement diff implementation.
